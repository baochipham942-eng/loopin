# Loopin 完整 Plan 与各端 Spec

> 来源：2026-06-05 与 Codex（艾克斯）的产品共创会话。本文件由 Claude 于 2026-06-06 从会话中持久化到 repo，作为开发依据（此前只存在于对话里，未落盘）。

## Summary

Loopin 定位为"面向年轻人的同频活动入口 + 面向主办方的活动赚钱与增长系统"。

核心判断：不要做新的活动行，也不要只做报名工具。Loopin 的差异是把一场活动从"选题、算账、生成活动页、招募、收费、到场、复办"串起来，让主办方知道这场活动能不能赚钱，也让 C 端用户觉得这不是普通讲座，而是一个值得去、能遇见同频人的局。

MVP 聚焦 20-100 人的行业分享、AI 沙龙、产品增长、创业出海、主理人活动。第一版支持免费报名和白名单付费活动，不开放所有主办方自助售票，不做活动发现广场，不做自动分账。

- 产品名：**Loopin**
- C 端口号：Find your people. Join the moment.（找到同频的人，加入正在发生的局）
- B 端名称：**Loopin Studio**

## Product Scope

MVP 必须完成一条闭环：

活动想法 → 行业选题推荐 → 盈亏测算 → 生成活动页和报名表 → 微信小程序报名/付费 → 推广物料生成 → 报名增长建议 → 签到 → 活动复盘与下一场建议

MVP 不做：

- 不做公开活动发现广场
- 不做复杂票务平台
- 不做开放式多主办方自动收款
- 不做自动分账
- 不做场地供应链撮合
- 不做赞助商市场
- 不做 App
- 不做完全自动投放
- 不做重会务系统和企业展会能力

默认：白名单邀请制主办方；活动类型 AI 分享/行业沙龙/产品增长/创业出海/主理人；客单 免费票/审核票/99·199·299 付费票；规模 20-100 人；城市先不限但成本模板优先一线/新一线。

## C 端微信小程序 Spec

C 端目标：让年轻用户觉得"这个局值得去，能认识厉害讲师和同频的人"。

核心页面：

1. **活动详情页**：首屏（活动名/时间地点/价格/主办方/核心卖点/报名按钮）；"这是什么局"（适合谁/能认识什么人/讲师为什么值得听/现场形式）；可公开参与者标签；主办方和讲师 profile；氛围图/海报/过往照片；免费/审核/付费票；分享与生成海报
2. **报名页**：微信登录 → 填报名表字段（手机号先手填，类目权限满足后可加微信手机号授权）→ 票种选择 → 付费走微信支付 → 审核活动进待审核 → 免费活动直接成功或进审核
3. **报名成功页**：报名状态（已报名/待审核/已通过/候补）；订阅提醒；加群引导；分享卡片；查看票夹
4. **我的活动**：已报名/待审核/已通过/候补中/已签到/已结束；活动资料包与下一场推荐
5. **活动票夹**：活动二维码/订单状态/退款状态/签到状态/活动提醒
6. **会后页**：活动资料包/讲师资料/精选问题/反馈问卷/同类推荐/关注主办方

体验原则：报名表默认 ≤5 字段；首次填资料后续同主办方可复用；活动页像"城市生活/同频社交"而非企业会议；公开参与者信息须用户主动授权；对用户展示"同频感"，对主办方沉淀"画像数据"。

## B 端 Loopin Studio Spec

B 端目标：让主办方从一个想法开始，判断能不能赚钱，并生成可执行的招募方案。

1. **活动选题雷达**：输入行业/城市/人群/形式 → 输出 5-10 个选题（推荐理由/目标人群/建议票价/建议规模/竞品参考/潜在嘉宾/潜在赞助/风险/市场信号/来源拆解）；MVP 数据源半自动维护，支持 `TopicSignal` 落库、运营录入、外部信号注入、JSON feed 定时同步和来源目录查询；可一键进盈亏测算
2. **活动赚钱计算器**：输入 票价/目标人数/到场率/场地费/茶歇费/物料费/嘉宾费/人力成本/推广费/赞助收入 → 输出 保本人数/预计利润/亏损边界/利润率/人数敏感性/票价建议；支持 30·50·100 人三档对比；有/无赞助对比；生成一句核心判断
3. **活动页 AI Designer**：输入主题/人群/风格/票价/嘉宾 → 生成标题/卖点/议程/讲师介绍/适合人群/FAQ/报名须知；3-5 套模板（AI 科技感/城市沙龙/创业路演/职场成长/主理人局）；可改文案图片；一键发布到小程序详情页
4. **可配置报名表**：字段类型（文本/手机号/单选/多选/长文本/职业标签/城市/公司/微信号/来源渠道）；属性（必填/选填/公开展示/仅主办方可见/审核参考）；按活动类型推荐字段；报名审核；候补名单；导出名单
5. **票种与收款**：免费/审核/付费票；付费仅白名单开放；第一阶段平台统一收款或绑定单一主办方商户号；库存/早鸟价/普通价/邀请码票；手动退款；不做自动分账
6. **推广物料生成**：朋友圈文案/微信群话术/小红书笔记/公众号短文/嘉宾邀请话术/赞助招商话术/分享海报；每渠道 2-3 版本；可按报名进度重新生成
7. **报名增长看板**：报名/付费/待审核/候补人数；渠道来源；票种销量；表单画像；保本进度；预计利润；no-show 风险；今日建议动作
8. **Agent 运营建议**：每天按报名进度给行动建议（换标题/补发话术/开放候补/提醒未支付/找合作社群/调整票价/控成本）；不自动投放/涨价/退款；高影响动作主办方确认
9. **复盘与复办**：输出 报名/到场/到场率/收入/成本/利润/渠道效果/人群画像/反馈摘要；会后反馈问卷和资料链接落库并进入复盘；按报名来源、物料渠道和 UTM 漏斗事件输出归因；自动分层用户（高意愿复购/潜在嘉宾/潜在赞助/报名未到场/下次可邀请）；生成下一场选题和复邀话术

## 现场端 Spec

主办方在小程序或 Web 移动页的"现场模式"：扫码签到；手动搜索姓名/手机号签到；查看已签到/未签到/候补；候补补位；现场临时通过报名；查看票种与支付状态；标记特殊用户（嘉宾/赞助/VIP/工作人员）；一键生成签到统计。

MVP 不接硬件，不做胸牌打印/复杂闸机/多人权限体系。默认一个主办方账号 + 若干工作人员扫码权限。

## Backend / Data / Agent Spec

核心数据对象：User（参会者）、Organizer（主办方）、HostProfile（主办方主页）、Event（活动）、EventPage（活动页配置）、TicketType（票种）、RegistrationForm（报名表 schema）、Registration（报名记录，含 checkinToken）、WaitlistEntry（候补记录）、Order（订单）、Payment（支付记录）、CheckIn（签到记录，registrationId 唯一防重复核销）、Channel（推广渠道）、Material（推广物料）、EventResource（会后资料）、TopicSignal（选题雷达市场信号）、BudgetPlan（成本与收入测算）、SponsorPlan（赞助方案）、AgentTask（Agent 建议任务）、EventReview（活动复盘）、EventFeedback（会后反馈）。

签到核验 payload 使用结构化 `loopin.checkin` 数据，至少包含 eventId、registrationId、token；扫码端按字段解析和校验，不能靠 substring 切位。

关键状态：

- Registration：draft / submitted / approved / rejected / waitlisted / cancelled / checked_in
- Order：pending / paid / refunded / cancelled
- Event：draft / published / closed / completed / cancelled
- AgentTask：suggested / accepted / dismissed / completed

Agent 分层：

1. **AI Generation**：生成标题/文案/海报/话术/FAQ/表单字段
2. **Decision Agent**：基于预算模型/报名数据/渠道数据生成建议
3. **Operator Agent**：仅执行低风险动作（提醒/候补通知/会后触达）；高风险动作（改票价/退款/取消/公开发布/赞助沟通）必须主办方确认

确定性系统（不能交给大模型自由生成）：支付、退款、报名状态、表单校验、库存、签到、盈亏计算、权限、数据导出。

## Monetization

MVP 验证三种收费：①单场工具费 99/199/499；②付费票务抽成 3%-8% 或固定服务费（白名单试点）；③主办方订阅月费 199/499/999。MVP 默认先跑 单场工具费 + 白名单付费票务。

## MVP Acceptance Criteria

找 1-3 个真实主办方试点，每个至少跑 1 场真实活动。成功标准：主办方愿用 Loopin 承接真实报名；盈亏测算影响了票价/人数/成本决策；实际使用了生成的推广物料；有明确报名与签到数据；活动后能生成复盘与下一场建议；至少 1 个主办方愿付 99 元+单场工具费或接受票务服务费；至少 1 个愿下一场继续用。

关键数据指标：活动创建到发布 <30min；用户报名完成 <90s；报名表完成率 >70%；到场率可记录可解释；主办方主观省时 >2h；盈亏测算与实际可对比。

## Test Plan（摘要）

产品验证（选题质量/盈亏计算/表单配置/三种票流程/渠道来源/扫码签到/复盘）；技术验证（小程序登录与手机号绑定/支付/表单 schema 渲染/状态流转/库存扣减/支付回调/手动退款/签到核验/海报生成/Agent 建议记录）；风险验证（未授权不展示个人信息/付费失败不出票/退款后票失效/候补转正库存正确/主办方数据隔离/Agent 不自动执行高风险动作）。

## Assumptions

- 小程序主体和基础资质可用（AppID `wxfb83ad53ee194fe3`）
- 第一版主办方白名单邀请制；付费活动不开放自助入驻售票
- 第一版不依赖平台流量，依赖主办方私域推广
- 第一版 AI 数据源半自动维护，不要求全自动抓取
- 第一版页面模板先做少量高质量模板，不做完全自由设计器
- 第一版不承诺自动盈利，只给测算、建议和执行工具
- C 端品牌 Loopin，B 端 Loopin Studio
